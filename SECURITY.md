# Security policy

Report suspected security problems privately. Do not include credentials, investigation content, personal data, or actionable vulnerability details in public issues or pull requests.

## Supported versions

| Component | Supported | Not supported |
|---|---|---|
| Client: threatcaddy.com and the standalone file | 2.1.0 | Earlier versions |
| Team server | 2.1.0 | Earlier versions |
| Browser extension | 1.1.5, from the [GitHub release](https://github.com/peterhanily/threatcaddy/releases/latest) | Earlier versions, including the Chrome Web Store's 1.1.1 |

Security fixes target the current `main` branch and ship in the next release; backports are not guaranteed. ThreatCaddy 2.1.0 still works with extension 1.1.3 and 1.1.4, but fixes go only into the newest extension. The Chrome Web Store's 1.1.1 has no app pairing, and its web fetch follows redirects and accepts private addresses; ThreatCaddy 2.1.0 uses none of its features. Forks and independently hosted deployments may not contain the same fixes; compare their source and version before relying on a fix.

## Reporting a vulnerability

Report it privately through GitHub's private vulnerability reporting: [Report a vulnerability](https://github.com/peterhanily/threatcaddy/security/advisories/new). [threatcaddy.com/.well-known/security.txt](https://threatcaddy.com/.well-known/security.txt) points to the same form. If the form is unavailable, open a public issue requesting a private contact channel, without describing the vulnerability or attaching evidence, and wait for a private channel before sharing details.

Include the affected component, release version or commit, deployment type, expected security boundary, observed impact, and a minimal description using synthetic data. Redact tokens, cookies, connection strings, browser profiles, exports, and production logs.

## What to expect

ThreatCaddy is a personal open-source project with one maintainer. On a best-effort basis, the maintainer aims to acknowledge a report within 7 days and to share an assessment, with a planned fix or the reason for declining, within 30 days. These are best-effort aims, not commitments, and there is no bounty. Coordinate disclosure with the maintainer: please wait until a fixed release is published, or until you have agreed a date, before you disclose details.

## How fixes are announced

A fixed vulnerability is announced in a [GitHub security advisory](https://github.com/peterhanily/threatcaddy/security/advisories) for this repository, and in a **Security** section of the [CHANGELOG](CHANGELOG.md) and of the release notes in [docs/releases](docs/releases) for the version that fixes it.

## Security boundaries

- Local investigation data lives in browser storage. Export a verified backup; browser storage and offline caches can be evicted.
- Local encryption covers supported content fields while locked. It is not whole-profile encryption, protection from a compromised browser, or end-to-end encryption for team synchronization.
- The hosted app and the standalone file do not run inside a frame, and the standalone file runs only when opened from a file. The hosted content security policy allows no inline script other than the page's own, but still allows the cloud-storage endpoints that cloud backup uses and local addresses for local AI models and team servers; see the [2.0.4 known limitations](docs/releases/v2.0.4.md#known-limitations).
- Optional AI, enrichment, map, backup, extension and team-server features can send data to their configured services. Review their configuration and permissions before use.
- AI tool calls are judged by where they reach, because investigation content can carry instructions aimed at CaddyAI and agents. The app checks every call again when it runs, and an approval covers only the exact call approved. An investigation that can sync is any investigation that is not local-only, whether or not a team server is connected yet, including a team investigation viewed without syncing it to this device.
  - **Without approval:** CaddyAI reads the investigation a conversation works in; in YOLO mode it also changes that investigation and runs built-in vendor lookups. From a local-only investigation, CaddyAI in Act or YOLO mode also lists, searches and reads other investigations; a conversation outside any investigation (none filed and none selected) reads every investigation. Both include local-only investigations. What AI writes in a local-only investigation, conversations included, does not sync while the investigation stays local-only; turning local-only off asks first when the investigation holds such content, because it can quote other investigations, local-only ones included. That question is a best-effort check (see the [2.0.3 known limitations](docs/releases/v2.0.3.md#known-limitations)); exports and share links of the investigation include such content without asking. Deployed agents, and the default agent that runs when none is deployed, do what their investigation's auto-approve settings allow inside it; until settings are saved for that investigation, each deployed agent's own settings apply and the default agent uses the default settings. Lead and executive agents also delegate tasks and review completed tasks inside the investigation, whatever the settings. The only outbound calls these settings can allow are built-in vendor lookups and fetches from a fixed list of reference sites (NVD, CVE, CWE, MITRE ATT&CK, CISA, FIRST). A profile that lists the cross-investigation tools, such as Pattern Hunter, deployed in a local-only investigation also reads other investigations, local-only ones included, as the reads setting allows. The supervisor reads across investigations and writes in its own local-only investigation, as the auto-approve settings allow. With the agent bridge turned on, page scripts read and change the selected investigation and list the names of investigations (leaving out local-only ones while an investigation that can sync is selected). Changes that run without approval inside an investigation that syncs reach its members through sync.
  - **Always asks:** CaddyAI opening any web page, and agents opening one outside the reference list; integrations other than the built-in vendor lookups, which run only from a lookup a person approves (in YOLO mode and in agent lookups the settings allow, they are skipped rather than asked); skills, SIEM and ticket calls; agent changes made from chat, and agents' proposals to spawn, define or dismiss agents or record a lesson; writes into another investigation from chat or the supervisor; chat reads of other investigations from an investigation that can sync; and writes, outbound calls or agent changes taken from reply text rather than sent as tool calls.
  - **Refused:** any read or write of a local-only investigation from AI working in an investigation that can sync (CaddyAI's list and search results say only how many investigations were left out); agents writing to other investigations, or reading them (except a profile that lists the cross-investigation tools, such as Pattern Hunter, deployed in a local-only investigation); agents deploying, stopping or running agents; in Plan mode, anything but reading the conversation's investigation (or, outside any investigation, reading without the cross-investigation tools); outbound calls and agent changes by the supervisor, and supervisor notes and tasks in an investigation that can sync (approving one that 2.0.2's supervisor queued in its older investigation fails); updating or reviewing an escalated task, or adding links from it, by agents, the supervisor or the agent bridge; and, through the agent bridge, which is off by default, anything else outside the selected investigation, off the device or changing agents.
  - **Between investigations:** the supervisor's reasoning, which can draw on every investigation, stays in its own local-only investigation. A proposal it files in another investigation carries a fixed note instead (proposals and actions that 2.0.2's supervisor recorded keep 2.0.2's reasoning, which their cards show on this device), and `list_agent_activity` leaves out supervisor proposals and server history. The proposal's own input, such as IOC notes it proposes, can still quote other investigations, local-only ones included: it is shown on the proposal's card and kept with the proposal on this device and in backups, whether approved or rejected. An export of another investigation gives every supervisor proposal, older ones included, the fixed note, and keeps the input and result text only of proposals that were carried out. An approved dismissal records only a dated lesson and a lower score in the dismissed agent's soul, which that agent reads in every investigation; the reason and evidence stay in the dismissal note. An export of an investigation includes the profiles of the agents deployed in it, souls included, so it can carry what those agents recorded in other investigations, local-only ones included; check the souls before you share the file.
  - Web fetch refuses private, local, literal-IP and credentialed addresses and needs extension 1.1.3 or later, like every extension feature. It cannot detect a public name that resolves to a private address.
- A team-server operator controls its database, files and secrets. Preserve the existing encryption keys and follow the [deployment and recovery guidance](docs/deployment.md) before upgrading.

Test only systems and data you are authorized to use. Do not probe the hosted application, other users' data, third-party providers, or production servers to substantiate a report.
