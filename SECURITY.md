# Security policy

Report suspected security problems privately. Do not include credentials, investigation content, personal data, or actionable vulnerability details in public issues or pull requests.

## Reporting a vulnerability

Use **Report a vulnerability** on the repository's [Security advisories page](https://github.com/peterhanily/threatcaddy/security/advisories) when that option is available. If it is unavailable, open a public issue requesting a private contact channel, without describing the vulnerability or attaching evidence. Wait for a private channel before sharing details.

Include the affected component, release version or commit, deployment type, expected security boundary, observed impact, and a minimal description using synthetic data. Redact tokens, cookies, connection strings, browser profiles, exports, and production logs. Coordinate disclosure with the maintainer; no response deadline or bounty is promised.

## Supported fixes

Security fixes target the current `main` branch. Older tags, forks, browser-store packages, and independently hosted deployments may not contain the same fixes; compare their source and version before relying on a fix. Backports are not guaranteed.

## Security boundaries

- Local investigation data lives in browser storage. Export a verified backup; browser storage and offline caches can be evicted.
- Local encryption covers supported content fields while locked. It is not whole-profile encryption, protection from a compromised browser, or end-to-end encryption for team synchronization.
- Optional AI, enrichment, map, backup, extension and team-server features can send data to their configured services. Review their configuration and permissions before use.
- AI tool calls are judged by where they reach, because investigation content can carry instructions aimed at CaddyAI and agents. The app checks every call again when it runs, and an approval covers only the exact call approved.
  - **Without approval:** CaddyAI reads the investigation a conversation works in; in YOLO mode it also changes that investigation and runs built-in vendor lookups. From a local-only investigation, CaddyAI in Act or YOLO mode also lists, searches and reads other investigations; a conversation outside any investigation (none filed and none selected) reads every investigation. Both include local-only investigations. Deployed agents, and the default agent that runs when none is deployed, do what their investigation's auto-approve settings allow inside it; until settings are saved for that investigation, each deployed agent's own settings apply and the default agent uses the default settings. Lead and executive agents also delegate tasks and review completed tasks inside the investigation, whatever the settings. The only outbound calls these settings can allow are built-in vendor lookups and fetches from a fixed list of reference sites (NVD, CVE, CWE, MITRE ATT&CK, CISA, FIRST). A profile that lists the cross-investigation tools, such as Pattern Hunter, deployed in a local-only investigation also reads other investigations, local-only ones included, as the reads setting allows. The supervisor reads across investigations and writes in its own local-only investigation, as the auto-approve settings allow. With the agent bridge turned on, page scripts read and change the selected investigation and list the names of investigations (leaving out local-only ones while an investigation that can sync is selected). Changes that run without approval inside an investigation that syncs reach its members through sync.
  - **Always asks:** CaddyAI opening any web page, and agents opening one outside the reference list; integrations other than the built-in vendor lookups, which run only from a lookup a person approves (in YOLO mode and in agent lookups the settings allow, they are skipped rather than asked); skills, SIEM and ticket calls; agent changes made from chat, and agents' proposals to spawn, define or dismiss agents or record a lesson; writes into another investigation from chat or the supervisor; chat reads of other investigations from an investigation that can sync; and writes, outbound calls or agent changes taken from reply text rather than sent as tool calls.
  - **Refused:** any read or write of a local-only investigation from AI working in an investigation that can sync; agents writing to other investigations, or reading them (except a profile that lists the cross-investigation tools, such as Pattern Hunter, deployed in a local-only investigation); agents deploying, stopping or running agents; in Plan mode, anything but reading the conversation's investigation (or, outside any investigation, reading without the cross-investigation tools); outbound calls and agent changes by the supervisor; changes to escalated tasks by agents, the supervisor or the agent bridge; and, through the agent bridge, which is off by default, anything else outside the selected investigation, off the device or changing agents.
  - **Between investigations:** the supervisor's reasoning, which can draw on every investigation, stays in its own local-only investigation. A proposal it files in another investigation carries a fixed note instead, and `list_agent_activity` leaves out supervisor proposals and server history. The proposal's own input, such as IOC notes it proposes, can still quote other investigations, local-only ones included: it is shown on the proposal's card and kept with the proposal on this device and in backups, whether approved or rejected. An export of another investigation gives every supervisor proposal, older ones included, the fixed note, and keeps the input and result text only of proposals that were carried out. An approved dismissal records only a dated lesson and a lower score in the dismissed agent's soul, which that agent reads in every investigation; the reason and evidence stay in the dismissal note. An export of an investigation includes the profiles of the agents deployed in it, souls included, so it can carry what those agents recorded in other investigations, local-only ones included; check the souls before you share the file.
  - Web fetch refuses private, local, literal-IP and credentialed addresses and needs extension 1.1.3 or later. It cannot detect a public name that resolves to a private address.
- A team-server operator controls its database, files and secrets. Preserve the existing encryption keys and follow the [deployment and recovery guidance](docs/deployment.md) before upgrading.

Test only systems and data you are authorized to use. Do not probe the hosted application, other users' data, third-party providers, or production servers to substantiate a report.
