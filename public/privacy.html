Privacy Policy

Last updated: November 25, 2026

ThreatCaddy is a personal open-source project. It is not affiliated with any employer, organization, or company — past, present, or future.

Data Storage

  • Notes, tasks, timelines, CaddyAI conversations and other investigation data are stored locally in your browser using IndexedDB. Optional features described below can transmit selected content, identifiers, or requests to other services.
  • Identities (people, organizations, systems and accounts you record) are stored with the investigation. Details marked private are masked until you choose Show and are not shown while screensharing. Copies kept so an AI change can be undone are deleted with the identity. Names you choose to ignore are remembered on this device as hashes, encrypted when local workspace encryption is on.
  • Extension clips are stored in chrome.storage.local on your device.
  • The standalone HTML file and the default web app require no accounts and use no cookies.

Optional Team Server

  • You may optionally connect to a self-hosted team server for real-time sync and collaboration. This is entirely opt-in — no data is sent until you configure a server URL and sign in.
  • When connected, notes, tasks, timelines, IOCs, and other investigation entities are transmitted to the server you configure. A CaddyAI conversation in an investigation that is not local-only is transmitted too; conversations outside any investigation and in local-only investigations are not synced. Authentication tokens are stored in your browser.
  • Local workspace encryption protects covered browser fields at rest; it is not end-to-end encryption for team sync. The server receives readable entity values and may retain historical records. Removing a server record does not erase offline copies or exported files.
  • Identities sync to a server that supports them, details marked private included. The server keeps earlier revisions in its history, records identity changes in its activity log without names, and does not give identity records to its bots. A chat or agent conversation that quotes identity tool results (names and public details) syncs like any other conversation, and bots that read conversations see it.
  • While you have a shared investigation open, the server tells its other members that you are there and which view you are on (for example Timeline), not which record. It keeps this in memory only and drops it within about 30 seconds of your leaving or closing the app. Nothing is sent for a local-only investigation.
  • The team server is open-source and self-hosted. This project does not provide a hosted team-server service; access and retention depend on the server operator you choose.

API Keys & AI Features

  • API keys you configure for AI features (e.g., OpenAI, Anthropic, Google, or other LLM providers) are stored locally in your browser.
  • Settings → AI → “Where AI data goes” shows the route AI requests take. A local model with a configured endpoint is called directly; only chat titles and conversation summaries reach it through the extension. Otherwise requests go through the browser extension or your team server: Browser Extension and Team Server routing use only that route, and Auto uses the team server while you are signed in to one, otherwise the extension. With no available route, nothing is sent. The extension receives client-configured credentials needed for its requests; a team server can use its own provider credentials, and its operator can read the prompts, investigation content and tool results that pass through it.
  • Prompts, selected context, attachments and tool results may contain investigation data. They are sent to the configured service when you use these features. Custom endpoints and proxies are additional trust boundaries; review their operators and retention policies.
  • Identity details marked private (such as a phone number or home address) are never included in tool results or context that ThreatCaddy sends to an AI service. Names and other identity details can be. Text that you or the AI write in a conversation is sent as written.

Extension Permissions

  • The extension uses permissions for clipping and delivery, and optional permissions for approved app connections, AI provider requests, URL fetching and desktop notifications.
  • Host permissions and app approval are separate controls. File access also depends on the browser's extension settings. Enabling an optional capability may allow selected content or requests to leave the device.
  • Clipping is user-initiated. Optional AI and URL-fetching operations process the requests and content you submit through those features; they are not limited to saved clips.

Analytics

  • The hosted site at threatcaddy.com loads no analytics. Its host, GitHub Pages, may separately retain ordinary request logs.
  • Self-hosted builds can enable Cloudflare Web Analytics when their operator supplies a build-time analytics token. The application does not inject this analytics script when that token is absent. Hosting providers may separately retain ordinary request logs.
  • The standalone HTML file and the extension include no analytics whatsoever.

Third Parties

Network activity depends on the features you use and the deployment configuration. These requests can reveal your IP address and request metadata to the receiving service. They include:

  • CaddyAI requests sent to the LLM provider endpoint you configure (e.g., api.openai.com).
  • Web pages you open with /fetch, and pages the AI asks to open once you approve them. Agents, including the default agent that runs when none is deployed, also open a fixed list of reference sites (NVD, CVE, CWE, MITRE ATT&CK, CISA and FIRST) without per-page approval when the investigation allows it, which it does by default. Private, local and literal-IP addresses are refused.
  • Sync traffic to a self-hosted team server, if you choose to configure one.
  • IOC enrichment and enabled integration requests to their configured services; submitted indicators can themselves be sensitive. When built-in vendor lookups (such as VirusTotal, AbuseIPDB and Shodan) are enabled, agents (when the investigation allows enrichment, which it does by default) and CaddyAI in YOLO mode run them without per-lookup approval.
  • Optional cloud-backup uploads, downloads and connection tests to the storage endpoint you configure. A connection test writes a small remote test object. Plain JSON exports are not encrypted; use the separate password-encrypted backup flow when needed.
  • Map-tile requests when you open map views. Tile providers can infer the viewed geographic area.
  • App assets and update checks from the site that serves the app. threatcaddy.com loads no analytics; a self-hosted build loads Cloudflare Web Analytics only if its operator enables it, as described under Analytics. Standalone offline operation does not require these hosted resources, but optional network features remain available when configured.
