# ThreatCaddy 2.1.2

This client/server release finishes live collaboration on a team server. In a
shared investigation the header now shows who else has it open and which view
they are on, and a change you make reaches your other signed-in devices within
about two seconds instead of with their next 30-second pull. There are no
database migrations and no stored data format changes. The extension stays at
1.1.5.

## Upgrade

If you use the hosted app, reload every open ThreatCaddy tab; if you use the
standalone download, save the 2.1.2 file over the earlier one, with the same
name and folder. **Settings → General → About** shows the version.

- **Presence** needs 2.1.2 in the browser only; it works with a 2.1.1 server.
- **Your own other devices** need a 2.1.2 server, and 2.1.2 on the device that
  makes the change. Upgrade the server as described in
  [upgrading the server](../../server/UPGRADING.md); there is no migration, so
  a 2.1.1 server can be put back.

Coming from 2.0.x, read the [2.1.0 upgrade and channel notes](v2.1.0.md)
first: 2.1.0 adds a database migration and has no downgrade.

## What changes

- **Presence.** While you have a shared investigation open, its other members
  see your name and the view you are on (for example Timeline) in the header.
  The app sends the view's name only, never a record. It sends nothing for a
  local-only investigation, and the indicator is hidden while screensharing.
  The server keeps presence in memory and drops you when you leave the
  investigation or close the app, or 30 seconds after your last update.
- **Your own other devices.** The server gives each connection an id when it
  signs in, the app names it when it sends a change, and the server then tells
  every other connection, yours included. The receiving device waits 1.5
  seconds before it syncs, so that a second tab of the same browser, which
  shares the outgoing queue, does not send the same change again.
- **Release checks (CI).** The job that publishes the hosted site can be
  re-run safely, and the check of the live site waits until every published
  file is served.

See [CHANGELOG.md](../../CHANGELOG.md) for the full list.

## Channels and verification

The channels, assets and verification steps are those of
[2.1.0](v2.1.0.md#channels-and-verification), with `v2.1.2` as the tag:

```sh
shasum -a 256 -c SHA256SUMS
gh release verify v2.1.2 --repo peterhanily/threatcaddy
gh release verify-asset v2.1.2 threatcaddy-standalone.html --repo peterhanily/threatcaddy
```

Publishing the image does not upgrade an existing team server, and this
release does not update a browser store.

## Known limitations

- Presence is kept per person, not per device: with two devices in one
  investigation, the others see the view reported last.
- A teammate still on 2.1.1 or earlier sends no presence, so they are not
  listed. On 2.1.1 they see one list for all their shared investigations,
  themselves included.
- With a server older than 2.1.2, a person who moves to another investigation
  stays listed in the first one for up to about 45 seconds.
- The [2.1.0 known limitations](v2.1.0.md#known-limitations) still apply.
