# ThreatCaddy 2.1.1

This client/server release fixes live team updates. The app now subscribes to
its shared investigations on the team server's WebSocket, so a teammate's
change arrives within about a second instead of with the next 30-second pull.
No earlier version sent the subscription, so the server's change announcements
reached no app; nothing was lost, changes only arrived later. There are no
database migrations and no stored data format changes. The extension stays at
1.1.5.

## Upgrade

The fix is in the client. If you use the hosted app, reload every open
ThreatCaddy tab; if you use the standalone download, save the 2.1.1 file over
the earlier one, with the same name and folder. **Settings → General → About**
shows the version. Every teammate who should receive changes at once needs
2.1.1.

The team server needs no upgrade for the fix: a 2.1.1 client receives live
changes from a 2.1.0 server. The 2.1.1 server image differs from 2.1.0 only in the version it
reports. Coming from 2.0.x, read the
[2.1.0 upgrade and channel notes](v2.1.0.md) first: 2.1.0 adds a database
migration and has no downgrade.

## What changes

- **Live changes.** The app subscribes to each investigation that is shared
  and that the server already holds, after it has signed in to the WebSocket.
  It sends the subscriptions again after a reconnect, and adds or drops one
  when an investigation is shared, joined, removed or made local-only.
- **Unchanged.** The 30-second pull still runs, so a missed announcement is
  caught up as before. An announcement carries the table, the record id and
  the author, never the content; the app then pulls the change.

See [CHANGELOG.md](../../CHANGELOG.md) for the full list.

## Channels and verification

The channels, assets and verification steps are those of
[2.1.0](v2.1.0.md#channels-and-verification), with `v2.1.1` as the tag:

```sh
shasum -a 256 -c SHA256SUMS
gh release verify v2.1.1 --repo peterhanily/threatcaddy
gh release verify-asset v2.1.1 threatcaddy-standalone.html --repo peterhanily/threatcaddy
```

Publishing the image does not upgrade an existing team server, and this
release does not update a browser store.

## Known limitations

- Presence (who else has an investigation open) is still not shown: the app
  sends no presence updates.
- Your own other devices still receive your changes with the 30-second pull,
  because the server does not announce a change to its author.
- The [2.1.0 known limitations](v2.1.0.md#known-limitations) still apply.
