# ThreatCaddy 2.0.3

This client/server release hardens CaddyAI chat, AgentCaddy agents, the
supervisor and the agent bridge against instructions planted in investigation
content (prompt injection). Each AI tool call is now decided by where it
reaches. A person approves every write into another investigation and every
tool call that sends data off the device, apart from built-in vendor lookups
and agents' fetches from a short list of reference sites. Changes AI makes
inside an investigation that syncs still sync to its members. AI working in an
investigation that can sync cannot see local-only investigations, and Settings
→ AI shows where AI data goes. The release also replaces the permanent offline
strip. The server code is unchanged apart from its version, and there are no
database migrations. The extension is released at 1.1.4; this release does not
assert that a browser store has published that version.

## Upgrade

Before upgrading, save drafts and create a full backup as described in the
[2.0.2 upgrade notes](v2.0.2.md#upgrade). 2.0.3 changes no stored data format,
so 2.0.2 and 2.0.3 backups restore in either version. Ask every member of a
team to upgrade: teammates still on 2.0.2 do not have these protections.

If you use the standalone download, save the 2.0.3 file over the 2.0.2 one,
with the same name and folder: some browsers, such as Firefox and Safari, tie a
local file's storage to its location, so a copy opened from elsewhere starts
empty.

If you use the hosted app, the first time you open it after the update the tab
can still run 2.0.2 from its offline copy, and until it reloads it runs 2.0.2,
including 2.0.2's AI behaviour. Reload every open ThreatCaddy tab before you
continue. If a view shows "Something went wrong" ("Failed to fetch dynamically
imported module" in Chromium-based browsers, "Importing a module script
failed." in Safari), reload the page; the view's own Reload button is not
enough. From 2.0.3 on, when a view fails this way after an update, the app
reloads the page by itself, once for each new version, also offline when the
installed app's service worker serves the page. **Settings → General → About**
shows the version, so you can check that each tab, and the standalone file,
runs 2.0.3.

What changes the first time you use 2.0.3:

- **Offline use.** The hosted app no longer shows a permanent offline strip. A
  notice appears only when you need to act: "Keep this tab open" while a slow
  first offline install runs, or a dismissible note when saving for offline use
  failed or this browser cannot keep ThreatCaddy offline. **Settings → General →
  Offline use** states the current status, and **Settings → Data** says, under
  Export & Import, that offline use is not a backup. The standalone file shows
  none of this.
- **AI routing.** **Settings → AI → Where AI data goes** shows the route AI
  requests take, and it is the route used. A local model with an endpoint is
  called directly; only chat titles and conversation summaries still go to it
  through the extension. Browser Extension and Team Server routing use only
  that route and no longer switch silently. Auto uses the team server while you
  are signed in to one, otherwise the extension. With no route, nothing is sent:
  chat, agents, meetings and the supervisor say why. The section shows a line
  for your local model and one for cloud providers; when cloud requests go
  through a team server, it names that server and says its operator can read
  your prompts, the investigation content the AI reads and tool results.
- **Web fetch and the extension.** Web fetch for CaddyAI and agents needs the
  ThreatCaddy extension 1.1.3 or later, approved for this app. Older versions
  are refused. At the time of this release the Chrome Web Store still offers
  1.1.1, so for web fetch install 1.1.4 from this release's downloads. Unzip
  `threatcaddy-chrome.zip` or `threatcaddy-firefox.zip` into a new folder and
  follow the [manual install steps](../../extension/README.md#install--chrome):
  in Chrome, turn on Developer mode and choose Load unpacked; in Firefox, load
  it as a temporary add-on, which Firefox removes when it closes, until a
  signed build is available. Then approve ThreatCaddy in the extension's
  popup. When two ThreatCaddy extensions are installed, the one that loads
  first serves the page, and ThreatCaddy checks that extension at every fetch.
  Keep only the newest one enabled, then reload the ThreatCaddy page.
- **CaddyAI chat.** CaddyAI now asks before it opens any web page, uses a
  skill, changes agents, writes into another investigation, or reads other
  investigations from an investigation that can sync. YOLO no longer skips
  these; it auto-approves only changes inside the conversation's investigation
  and built-in vendor lookups, and its off position is labelled "Ask" instead of
  "Safe". Plan mode only reads (inside an investigation, only that one).
  Approval cards queue one at a time above the composer, and Enter no longer
  approves.
- **Local-only investigations** are invisible to chat, agents and the agent
  bridge working in an investigation that can sync. An investigation can sync
  when it is not local-only, whether or not a team server is connected yet:
  connecting one later shares it. In a workspace that has never been connected
  to a team server, an investigation's settings now show a **Keep on this
  device** switch; while connected, use **Cloud Sync**. Local-only keeps an
  investigation out of team sync, but AI requests about it still follow the AI
  route, which can be the team server.
- **Agent settings are a limit.** An investigation's saved auto-approve
  settings now limit every agent deployed in it; an agent's own settings can
  turn an action off, never on. If an investigation has saved agent settings
  (2.0.2 also saved them, with creates on and changes off, when CaddyAI
  deployed an agent from chat), some built-in agents now ask before actions
  they used to run on their own. A one-time notice says so, and the agent
  settings list what each agent asks before doing. Turn an action on in the
  investigation's settings to let its agents run it again. Where no agent
  settings were saved, the limit applies only once you change one.
- **What agents run on their own.** Agents fetch automatically only from NVD,
  CVE, CWE, MITRE ATT&CK, CISA and FIRST, and run only built-in vendor lookups
  without approval. Other web pages, skills, and executives' spawn, define,
  dismiss and reflect actions become proposals. Team and community integrations
  and Slack notifications run only from an approved proposal or a manual run.
  Agents can no longer deploy, stop or run agents, or read or change other
  investigations (Pattern Hunter's comparisons aside, see below). Only the
  agent with a pending proposal pauses. **Approve all** runs routine actions
  inside the investigation only and leaves the rest for individual review.
- **Proposals queued by 2.0.2.** Approving a pending proposal that 2.0.3 no
  longer allows (for example to deploy an agent, create in another
  investigation, or read another investigation from one that can sync) marks it
  failed with the reason, and nothing runs. The reason is in your language
  when the proposal came from a team server; when its investigation is deleted
  or archived, or its agent or profile is gone; when the agent can no longer
  use the tool, or a skill or its input changed; or when what it targets is
  gone, moved or outside the investigation, read-only for the agent, or an
  escalated task. An agent host's or SIEM's answer is kept as it came, and
  other errors, such as "IOC not found or deleted", stay in English. Approving
  an agent's question acknowledges it.
- **Pattern Hunter** compares investigations only when deployed in a
  local-only investigation. In one that can sync, its card says the
  cross-investigation tools are off there. To compare cases, deploy it in a
  local-only investigation.
- **Supervisor.** The supervisor's findings come from every investigation, so
  it now keeps them in a new local-only "CaddyAgent Supervisor" investigation,
  and the Supervisor Briefing and the AgentCaddy dashboard show that one. An
  older "CaddyAgent Supervisor" investigation that can sync (one created by
  2.0.2, or a teammate's) stays as an ordinary investigation with its earlier
  findings, and the supervisor no longer writes to it. Rename the older one to
  tell the two apart; renaming the new one makes the supervisor start another.
  Renaming, archiving or deleting an investigation that syncs applies to every
  member, so delete it only when no teammate needs its findings. The new
  investigation starts with default agent settings, so the supervisor's notes
  and tasks wait for your approval; to let it write them on its own, turn on
  **Create** in that investigation's agent settings. The supervisor now asks
  before writing into other investigations and before any write taken from
  reply text. Its proposals in other investigations carry a fixed note, and its
  reasoning stays in its own investigation. A proposal's own input, such as IOC
  notes it proposes, can still quote other investigations, local-only ones
  included; it is shown on the proposal's card, so read it before approving,
  and kept with the proposal on this device and in backups. An export of any
  other investigation keeps the input and result text only of supervisor
  proposals that were carried out. The supervisor cannot reach the network or
  change agents.
- **Agent bridge.** The agent bridge (`window.threatcaddy`, used by browser
  automation such as the Claude Code skill over CDP) is off by default. Turn it
  on under **Settings → AI → Where AI data goes → Agent bridge** only while you
  use it: while it is on, any script on the page can use it. It works only in
  the investigation selected in ThreatCaddy (`tc folder <id>` no longer
  switches) and offers 33 tools. It cannot fetch web pages, run enrichment,
  read or change other investigations, or change agents; it can list
  investigation names. `investigations()` now needs the nonce, and the bridge
  reports version 1.2.0. Update your copy of the Claude Code skill
  (`agents/claude-code`) from this release: `tc investigations` from an older
  copy fails with "Invalid agent bridge nonce".
- **Agent hosts.** Named agent hosts can no longer be added or edited.
  Settings → AI lists the hosts kept from earlier versions with **Remove**.
  Named hosts that use plain http on an address other than localhost,
  127.0.0.1 or [::1] are no longer used. Every agent-host or local-skill call
  that CaddyAI or an agent makes asks first, whatever action class the host
  declares. CTI slash commands such as `/cti` and `/vt` need a host named `cti`
  kept from an earlier version; one that uses plain http to another computer is
  not used, and the command says it needs https.
- **Team templates** you install now start disabled, and a message lists the
  domains each one can contact. Review the template, then enable it on the
  Installed tab.

## Included changes

- **Chat approvals:** one card at a time for web pages, vendor lookups, skills,
  agent changes, writes and other investigations. Each card says what the call
  reaches; a write card names the investigation the change lands in and
  whether it syncs, or says the change stays on this device outside any
  investigation. Cards flag sites that are not reference sites, long
  data-carrying addresses, sites that are IOCs in the investigation and calls
  taken from reply text, and an enrichment card names each lookup in your
  language with its site. Plan mode only reads; YOLO covers in-investigation
  changes and built-in vendor lookups only, and the mode tooltips say what
  still asks.
- **Chat content:** chat, agent-audit and meeting messages no longer load remote
  images or media. Suggestion chips written by CaddyAI cannot run slash
  commands or mention entities, and @-mentions of trashed entities, or of
  local-only ones from an investigation that can sync, are left unresolved.
  **Export as note** files into the conversation's investigation; skill and
  agent-host results are capped at 50,000 characters; a new conversation says
  where its messages are kept and sent, without claiming encryption that is
  off.
- **Agents:** reference-site-only automatic fetches, built-in vendor lookups
  only without approval, approval for every agent change, no access to other
  investigations outside Pattern Hunter's local-only comparisons, investigation
  settings as a limit, per-agent pauses, routine-only **Approve all**, and a
  local-only supervisor. AI tools add no agent once 8 are active in the
  investigation, and no second copy of an active agent. Enrichment proposals
  name every destination and update when the IOC or the lookups change; on the
  hosted site, enrichment results name built-in lookups in your language. A
  dismissed agent stops after the call in progress, its proposals cannot run,
  and its soul records no dismissal text. Supervisor proposals in other
  investigations carry a fixed note, not its reasoning, `list_agent_activity`
  leaves them out, and exports leave out the input and result text of those
  not carried out. Statuses, the panel's counters and the dashboard's
  active-agent count (with plural forms), and the approval refusals described
  under [Upgrade](#upgrade) are in your language. The Server-Side Mode section
  is hidden while the team server cannot run agents, and when that pauses an
  agent, the panel says why and that the agent runs here once it is deployed
  again.
- **Provenance:** notes (including alert notes and note folders), tasks, IOCs
  and timeline events created by agents, the supervisor or the agent bridge
  record their creator on this device and carry an `ai-generated` tag that
  syncs. Entities created in chat stay attributed to you, without the tag.
  Reports the AI generates carry the tag even when made in chat, and meeting
  minutes always carry it.
- **Routing:** one rule for chat, agents, meetings, the supervisor and
  Settings; nothing is sent without a route; translated refusals that say what
  to do; the chat status shows the thread's route ("Local LLM", or "No
  connection" when there is none).
- **Web fetch and integrations:** private, local, literal-IP, credentialed and
  over-long addresses are refused before the extension is contacted; extensions
  older than 1.1.3 are refused; team templates install disabled; integration
  runs no longer post API keys to a missing team-server route.
- **Extension 1.1.4:** turns local-model text into tool calls only for an exact
  `<tool_call>` wrapper, advertises its guarded web fetch, and leaves another
  ThreatCaddy extension's capabilities alone when that extension loaded first.
- **Agent bridge and hosts:** the bridge is off by default and limited to the
  selected investigation (version 1.2.0; `investigations()` needs the nonce);
  named hosts are read-only and need https; skill descriptions and parameters
  are sanitised, and skill names are aliased in transit so they no longer break
  Anthropic, OpenAI or Mistral requests.
- **Offline use and updates:** no permanent strip; status in Settings →
  General; backup note in Settings → Data; a view that cannot load its code
  after an update reloads the page once for each new version, also offline
  when the installed app's service worker serves it; the version in Settings →
  General → About.
- **Accessibility and translation:** screen readers announce approval cards and
  offline notices and hear the current Ask/YOLO setting with what it allows;
  the light-theme Approve label is readable; raw tool input, @-mention prefixes
  and `/fetch` commands read left to right in Arabic, Hebrew and Farsi; agent
  proposal expand buttons have correct accessible names; investigation details
  show real counts and dates; the screenshare menu, tag input, draft and
  remote-investigation banners, the standalone file's file:// warning and the
  investigation details dialog are translated; the remote banner now says that
  items you add while viewing it are saved on this device and queued to sync
  to that investigation on the team server, and the standalone warning that
  the content security policy does not restrict scripts or network
  connections; phone layouts of agent proposals and the agent hosts list no
  longer overlap or hide text, and in right-to-left languages a long Latin
  agent host or investigation name keeps its start visible.

See [CHANGELOG.md](../../CHANGELOG.md#v203--2026-11-18) for the full list.

## Channels and verification

| Channel | Identity to check |
|---|---|
| Hosted app and PWA | Served from the verified client build of this release's source |
| Standalone download | `SHA256SUMS`, `release-manifest.json` and the published asset digest |
| Server image | The GHCR digest and source revision in `release-manifest.json` |
| Chrome/Firefox extension ZIPs | Their own manifest version (1.1.4) and package hashes |
| Browser stores and running team servers | Checked separately; this release does not update them |

The 2.0.3 release assets are the standalone HTML file, the two extension ZIPs,
`release-manifest.json` (which records the source revision) and `SHA256SUMS`.
Download all of them before you run `shasum -c`, because `SHA256SUMS` also
covers `release-manifest.json`. threatcaddy.com serves the same client build.
The GHCR server image for this release reports version 2.0.3 in
`/health`; identify it by the digest and source revision in
`release-manifest.json`. Its server code is unchanged from 2.0.2 apart from the
version, and it adds no database migrations. Publishing an image does not
upgrade an existing server; follow
[deployment and rollback](../deployment.md#rollback-and-restore).

The release is published with GitHub immutable-release protection, so its tag
and assets cannot change after publication; corrections need a new version.
With the GitHub CLI you can check the downloads:

```sh
shasum -a 256 -c SHA256SUMS
gh release verify v2.0.3 --repo peterhanily/threatcaddy
gh release verify-asset v2.0.3 threatcaddy-standalone.html --repo peterhanily/threatcaddy
```

Maintainers assemble and verify releases as described in
[release maintenance](../repository-maintenance.md).

## Known limitations

- Instructions in investigation content can still steer what AI does without
  approval in the investigation it works in: reads; the changes your approval
  settings allow, and agents' audit threads and delegated tasks, which sync to
  the investigation's members if it syncs; built-in vendor lookups of its IOCs;
  and agents' fetches from the reference sites. The `ai-generated` tag and the
  investigation's limit make that work visible. Keep approval required for
  changes when working with untrusted material, and read each card's
  destination and flags before approving.
- 2.0.3 does not address forged chat history arriving through sync, spoofed
  knowledge or meeting tags, or imported agent profiles that carry hostile
  instructions. Every route out of the investigation is still gated.
- Agent souls recorded by 2.0.2 (identity, lessons, strengths and weaknesses)
  may contain injected text or text from another investigation: 2.0.2 recorded
  an agent's reflections without approval, and its dismissals recorded their
  reason and evidence. The agent's prompt in every investigation replays them,
  cleaned and marked as data. They stay in the soul, because 2.0.3 cannot edit
  a soul; deleting a single lesson is planned for 2.1. An investigation's
  export includes the profiles of the agents deployed in it, souls included,
  so it can carry what those agents recorded in other investigations,
  local-only ones included. Check the `agentProfiles` entries in the file
  before you share it.
- Web fetch refuses private, local and literal-IP addresses, but cannot detect a
  public name that resolves to a private address, because the extension cannot
  pin DNS. Approval and the reference-site list are the control.
- After you approve a read of other investigations in an investigation that can
  sync, what CaddyAI read becomes part of the conversation, which syncs to that
  investigation's members. The card says so before you approve.
- With Auto routing and a team-server sign-in, cloud-provider AI requests go
  through the team server, including the supervisor's, which reads every
  investigation, local-only ones too. Choose Browser Extension routing or a
  local model to keep them off the server.
- With the team-server route, chat thread titles and summaries of long
  conversations are skipped, because they can only use the extension.
- A manual Run also runs agents waiting for review. An agent can then ask a
  pending question again in other words, adding another question up to the
  investigation's limit (3 by default).
- An integration's installation scope is not enforced when an analyst starts
  enrichment (IOC menus, bulk enrichment, auto-enrichment of new IOCs). No
  2.0.3 control sets that scope; enforcement is planned for 2.1. Per-agent
  budgets are also planned for 2.1.
- The standalone file blocks remote images, audio and video in Chromium-based
  browsers only. Safari and other WebKit browsers ignore a content security
  policy in a file opened from disk.
- The hosted app's content security policy still allows the cloud-storage
  endpoints that cloud backup uses.
- An open tab keeps running the version it loaded until it reloads; an update
  does not reload open tabs. The app reloads by itself only when a view cannot
  load its code. That reload stops a CaddyAI answer that is streaming or an
  agent cycle that is running. If the page still runs the same version after
  that reload and another part of the app fails to load its code, the page can
  stay blank until you reload it.
- Once the main area shows "Something went wrong", it keeps showing it when you
  switch views, until you select its Reload button.
- In-app links to install the extension open the Chrome Web Store, which
  offers 1.1.1 at the time of this release. For web fetch, install 1.1.4 from
  the release downloads (see [Upgrade](#upgrade)). In Firefox, 1.1.4 is a
  temporary add-on: load it again after each restart until a signed build is
  available.
- On phones in Analyst Mode, the chat composer can be cut off at the bottom,
  the conversation title can collapse and the icons at the end of the
  conversation header can be cut off; scroll the page to reach the composer.
- **Open AI settings** in an agent's route refusal opens the top of Settings →
  AI; the routing select and Where AI data goes are further down.
- Some text stays in English: the runtime errors "LLM request was cancelled or
  timed out.", "Supervisor request was cancelled or timed out.", "Meeting LLM
  call timed out" and "Handoff failed: …"; error text from AI providers; tool
  errors such as "IOC not found or deleted", and the reasons of agent actions
  that failed under 2.0.2; the action types ("create", "modify") on the
  AgentCaddy dashboard's investigation cards; agent roles and the profile
  details, including the Soul section, in the agent profile list in Settings;
  and some backup-restore errors, such as "Invalid backup file format or
  unsupported version; nothing was imported."
- In some languages a few counts still read awkwardly, with an English plural
  ending or both singular and plural forms, for example the graph's "Found in
  N entities" and a meeting's round count.
- A failed agent-host or SIEM action shows the remote system's error text
  under Result without naming that system as its source.
- Backups, including investigation backups, keep supervisor proposals as
  stored: the reasoning of proposals filed before 2.0.3, and the input and
  result text of proposals that were not carried out, which an export of the
  investigation leaves out. To share an investigation, use its export, after
  checking the agent souls it includes (see the 2.0.2 souls item above).
- In an empty conversation, the line that names the investigation AI can read
  and create in follows the investigation selected in the sidebar, not the
  conversation's own.
- The Supervisor Briefing counts shared IOC patterns by looking for the English
  phrase "shared IOC" in the supervisor's three most recent notes.
- Firefox browser tests for this release run only in CI; local release checks
  covered Chromium and WebKit.
- Server AgentCaddy handoff and the legacy server integration runner remain
  unavailable. The [2.0.2 known limitations](v2.0.2.md#known-limitations) still
  apply.
