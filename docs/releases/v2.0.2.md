# ThreatCaddy 2.0.2

This client/server release is the first since 2.0.0. It includes everything
deployed as 2.0.1 (data-preservation and session fixes, bounded evidence
imports, accessibility and startup improvements, a realistic synthetic
investigation) and fixes the regressions an independent review found in 2.0.1.
2.0.1 itself was never released as downloads; see [2.0.1](v2.0.1.md).
The extension remains independently versioned at 1.1.3; this release does not
assert that a browser store has published that ZIP version.

## Upgrade

Before upgrading, save drafts and create a full backup, then verify it in a
separate browser profile. Team sync is partial and does not recover device-only
fields. **Save Backup** JSON is not password-encrypted; use encrypted backup and
separate key custody for independent recovery. See
[backup and recovery](../backup-recovery.md).

If a backup failed on 2.0.0 or 2.0.1, unlock the workspace on 2.0.2 and try
again: a one-time local repair fixes the records that blocked it. If it still
fails, the message now names the table, field and record.

Users of the 2.0.0 standalone download should replace it with the 2.0.2
standalone from this release. Save the new file over the old one, with the same
name and folder: some browsers, such as Firefox and Safari, tie a local file's
storage to its location, so a copy opened from elsewhere starts empty. Keep the
existing backup until the new copy is verified. 2.0.0 cannot import 2.0.2
backups that contain AI-delegated tasks, so keep a 2.0.0-era backup if you might
need to go back. Previously cached encryption sessions require a fresh
passphrase or recovery unlock. If you chose a 1-, 8- or 24-hour session, open
tabs now lock at that time; a warning two minutes before lets you stay unlocked. A release cannot recover fields that were
already lost without a usable copy.

In a workspace connected to a team server, restoring a backup now pauses team
sync instead of pushing deletions to teammates. Reconcile in **Settings →
General → Sync history recovery** before syncing again.

Team operators should preserve the matching database, managed files and
recovery keys, qualify a restore, then upgrade to the exact image digest in
this release's manifest. Follow
[deployment and rollback](../deployment.md#rollback-and-restore). Publishing an
image does not upgrade an existing server. Servers running any image published
after 2.0.0 (GHCR `latest` from 13 November 2026, including
`sha256:d97ee2c0…`; `/health` reports 2.0.0 or 2.0.1) should move to this
release's digest.

Docker deployments that do not use the repository Compose file and need the
admin panel must set `ADMIN_HOST=0.0.0.0` in the container and publish
administration only on host loopback (`127.0.0.1:3002:3002`), then reach it
through an SSH tunnel. On Kubernetes, leave `ADMIN_HOST` unset and use
`kubectl port-forward`; do not expose port 3002 through a Service. Never
combine `ADMIN_HOST=0.0.0.0` with `3002:3002` or host networking. The image runs
Node 24.22.3 with `NODE_ENV=production` (error responses no longer echo
exception messages), has no npm or npx (use the packaged
`node dist/...` commands) and declares a `/health` HEALTHCHECK. The tracked
Compose file now uses the `json-file` log driver for both services; to keep a
daemon-wide driver, see [logging](../deployment.md#48-logging).

## Included changes

- **Backup and restore:** backups succeed in every workspace state; restores in
  team-connected workspaces never push deletions; Export Investigation files
  always merge and cannot wipe other investigations; backups carrying sync
  revision metadata import; failures name the blocking record.
- **Team sync:** an unreadable server change is skipped and named instead of
  stopping sync for everyone; agent delegation no longer breaks uploads; share
  links no longer carry assignees or agent IDs; sync pauses while locked.
- **Evidence import:** bounded, cancellable parsing with atomic commits.
  Ordinary PDFs with screenshots and large workbooks import again (partially,
  with a warning); unreadable Office files and very large images import as
  metadata only; decompression stays bounded. The standalone file imports
  in Safari/WebKit, background reloads no longer cancel imports, and errors are
  translated and name the file.
- **Samples:** a realistic synthetic mailbox investigation by default; removing
  a sample asks first and can keep your additions; sample tags and timelines
  stay local.
- **Encryption and sessions:** locks happen at the real deadline, the 24-hour
  option lasts 24 hours, and a warning two minutes before a timed lock lets you
  stay unlocked. Changing servers signs out of the previous one; Disconnect is
  available while a server is unreachable.
- **Team server:** Node 24.22.3 and Hono 4.13.18 security updates; uploads
  authenticated before buffering; no SQL or password hashes in request errors or
  their logs; per-address login lockout; read-only viewers; administration on loopback.
- **Accessibility:** visible focus in every theme and colour scheme, dialogs
  that keep and return focus, and corrected contrast and landmarks.

See [CHANGELOG.md](../../CHANGELOG.md#v202--2026-11-16) for the full list.

## Channels and verification

| Channel | Identity to check |
|---|---|
| Hosted app and PWA | Served from the verified client build of this release's source |
| Standalone download | `SHA256SUMS`, `release-manifest.json` and the published asset digest |
| Server image | The GHCR digest and source revision in `release-manifest.json` |
| Chrome/Firefox extension ZIPs | Their own manifest version (1.1.3) and package hashes |
| Browser stores and running team servers | Checked separately; this release does not update them |

The release is published with GitHub immutable-release protection, so its tag
and assets cannot change after publication; corrections need a new version.
With the GitHub CLI you can check the downloads:

```sh
shasum -a 256 -c SHA256SUMS
gh release verify v2.0.2 --repo peterhanily/threatcaddy
gh release verify-asset v2.0.2 threatcaddy-standalone.html --repo peterhanily/threatcaddy
```

The historical 2.0.0 tag and assets remain available unchanged. Maintainers
assemble and verify releases as described in
[release maintenance](../repository-maintenance.md).

## Known limitations

- Team sync is partial and not end-to-end encrypted. Local content encryption
  does not encrypt the whole browser profile.
- While someone keeps failing sign-ins to an account from several addresses, a
  legitimate user signing in from a new address, or from any address after a
  server restart, can be refused until the attempts stop. Behind a reverse proxy
  the server does not trust (`TRUSTED_PROXY_IPS`), all users share one address,
  so five failures lock the account for everyone, as in 2.0.0.
- A purge removes an investigation's current data but does not erase its sync
  history, audit entries or database backups.
- AI agents and CaddyAI act on investigation content, which can contain hostile
  instructions. Keep approval required for fetch and write actions when working
  with untrusted material.
- Server AgentCaddy handoff and the legacy server integration runner remain
  unavailable. The server is single-process per database.
