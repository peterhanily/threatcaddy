# ThreatCaddy 2.1.0

This client/server release adds Identities: a place to record the people,
organizations, systems and accounts in an investigation, linked to the
timeline, notes, IOCs, the graph, reports, Products and AI. The browser
database moves to version 35 (a new `identities` table; no existing table
changes), and the team server adds migration `0025_identities`. There is no
downgrade: see [Upgrade](#upgrade). The browser extension is unchanged (1.1.5).
The [CHANGELOG](../../CHANGELOG.md) lists every change, and the README's
Identities section describes the feature.

## Upgrade

Before upgrading, save drafts and create a full backup as described in the
[2.0.2 upgrade notes](v2.0.2.md#upgrade), and back up the team server's
database and managed files. Ask every member of a team to upgrade.

**Order.** The team server and its clients can be upgraded in either order:
- **A 2.0.4 client on a 2.1.0 server** keeps syncing as before and never
  receives identities. The server sends each client only the tables it asks
  for, and an identity change is announced without its record.
- **A 2.1.0 client on a 2.0.4 server** keeps its identities on the device, and
  the sync status says so. They sync once the server is upgraded.

If you use the standalone download, save the 2.1.0 file over the 2.0.4 one,
with the same name and folder, and open it from there: some browsers tie a
local file's storage to its location. If you use the hosted app, reload every
open ThreatCaddy tab. **Settings → General → About** shows the version.

What changes the first time you use 2.1.0:

- **The browser database upgrades in place** to version 35, including an
  encrypted workspace (unlock as usual). Every existing record stays as it was,
  and 2.0.4 backups restore.
- **Identities appear** in the sidebar, on investigation cards, in search, on
  the timeline (as Actor and Assets chips), in notes (`@` mentions), on IOCs
  ("Belongs to"), on the graph and in AI tools. Names on the timeline and on
  IOCs that are not yet identities are offered under **Not yet in Identities**.
- **Private details.** Details labelled as phone numbers, street addresses,
  personal email, birth dates, passport or national ID numbers and similar
  start out private. They are masked until you choose Show, never shown while
  screensharing, never sent to AI, and left out of the CSV export unless you
  tick them. They sync to the team server like other fields: see
  [Team server](#team-server).

**No downgrade:**
- A browser that has opened 2.1.0 cannot be opened by 2.0.4.
- A backup that contains identities, and any encrypted backup made by 2.1.0,
  needs 2.1.0 or later to restore. A portable backup without identities still
  restores in 2.0.4.

**Teams with 2.0.4 clients:** archiving or unarchiving an investigation in
2.0.4 does not change its identities. To bring them back, unarchive the
investigation in 2.1.0 (archive it first if 2.0.4 already unarchived it).

## Team server

- **Migration `0025_identities`** runs when the server starts. It is additive
  (one new table, its indexes and the sync triggers) and quick.
- **Rollback:** once the migration has run, a 2.0.4 server refuses to start on
  that database ("Unsupported or modified migration history"). Rolling back
  therefore means restoring the pre-upgrade database and file backup, which
  loses every write made since, and then rotating the sync history. See
  [migration recovery](../../server/docs/migration-recovery.md) and
  [sync history recovery](../../server/docs/sync-recovery.md).
- **What the database holds:** identities are stored readable, private details
  included. That covers every revision the sync history keeps, tombstones for
  the retention period, and a final copy when a row is removed for good. The
  activity log records identity changes by id and action, without names. See
  [what the database holds](../backup-recovery.md#what-the-database-holds).
- **Bots** never receive identity events and cannot read or write identities.

The supplied Compose installation builds the server image from source: update
the source, then `docker compose build server` and
`docker compose up -d --no-deps --force-recreate server`, as described in
[upgrading the server](../../server/UPGRADING.md).

## Channels and verification

| Channel | Identity to check |
|---|---|
| Hosted app and PWA | Served from the verified client build of this release's source |
| Standalone download | `SHA256SUMS`, `release-manifest.json` and the published asset digest |
| Server image | The GHCR digest and source revision in `release-manifest.json` |
| Chrome/Firefox extension ZIPs | Unchanged (1.1.5) |

The GHCR server image for this release reports version 2.1.0 in `/health` and
adds migration `0025_identities`. Identify it by the digest and source revision
in `release-manifest.json`, not by a tag. Publishing an image does not upgrade
an existing server; follow [deployment and rollback](../deployment.md#rollback-and-restore).
Maintainers assemble and verify releases as described in
[release maintenance](../repository-maintenance.md).

## Known limitations

- **Names in Chinese, Japanese and Thai text** are found by dictionary word
  boundaries. A two-character Chinese name can therefore also match inside a
  longer name the dictionary does not know (王伟 in 王伟东).
- **Turkish case:** names are compared without a language, so the dotless ı and
  i count as one letter (Yildiz matches Yıldız), as İ and I do.
- **Private details on the team server** stay in its sync history after they
  are removed or made private; history is not compacted.
- **Identities are not offered to server bots**, but chat and agent threads
  that quote identity tool results sync with their investigation like any
  other conversation.
