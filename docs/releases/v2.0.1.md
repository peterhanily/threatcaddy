# ThreatCaddy 2.0.1

This client/server patch includes the data-preservation and session fixes
previously deployed to the website after 2.0.0, plus bounded evidence imports,
accessibility/startup improvements and a realistic synthetic investigation.
The extension remains independently versioned at 1.1.3; this release does not
assert that a browser store has published that ZIP version.

## Upgrade

Before upgrading, save drafts and create a verified full backup. Team sync is
partial and does not recover device-only fields. Ordinary Save Backup JSON is
readable; use encrypted backup and separate key custody for independent recovery.
See [backup and recovery](../backup-recovery.md).

Users of 2.0.0 tagged standalone downloads should obtain the new standalone
from the [2.0.1 release](https://github.com/peterhanily/threatcaddy/releases/tag/v2.0.1).
Preserve the existing workspace and backup until the new copy is verified.
Previously cached encryption sessions require a fresh passphrase or recovery
unlock. A fixed release cannot recover fields already lost without a usable copy.

Team operators should preserve matching database, managed files and recovery
keys, qualify a restore, then upgrade to the exact image digest in this release's
manifest. Follow [deployment and rollback](../deployment.md#rollback-and-restore).
Publishing that image does not upgrade an existing server. Do not resume the
retained stack merely because the website changed.

## Included changes

- Accepted sync responses preserve unsupported local fields, and removal flows
  disclose the device-only boundary. Legacy server revisions remain backup-compatible.
- Encryption locks on its real deadline, including resume and shortened sessions;
  the selected 24-hour lifetime is honored. Unsaved encrypted recovery is tab-local.
- Logout revokes refresh families with expired/missing access tokens and reports
  remote-revocation failures. Administration defaults to loopback and bootstrap
  work is throttled. Hono and the published server-image runtime are hardened.
- Document imports enforce input, entry and actual decompression budgets, skip
  irrelevant ZIP content, and run in cancellable workers. A rejected/cancelled
  import does not leave partially committed evidence. Destination and encryption
  session ownership are rechecked at commit.
- Actionable text contrast, quick-link hit areas, main landmarks and headings are
  corrected. Startup locales are bundled and unopened sharing UI is deferred.
- The default demo is a clearly synthetic mailbox investigation with linked
  evidence, timeline, tasks and a reviewable report. The parody remains separately
  available. Reopening a loaded sample preserves edits.
- Browser CI retains original failure traces and treats retry-only success as a
  failed gate. Modal focus/keyboard handling is installed before paint.

See [CHANGELOG.md](../../CHANGELOG.md#v201--2026-11-15) for the versioned summary.

## Channels and verification

| Channel | Identity to check |
|---|---|
| Hosted app and PWA | The verified client artifact and post-publication hosted/offline smoke |
| Versioned standalone download | `release-manifest.json`, `SHA256SUMS`, published asset digest and qualified standalone bytes |
| Server image | Immutable GHCR digest and image config/source in the release manifest |
| Chrome/Firefox extension ZIPs | Independently versioned manifests and exact package hashes |
| Browser stores / running team servers | Separate installed version and operator rollout evidence |

The historical 2.0.0 tag/assets remain available for provenance; they are not
replaced with corrected bytes. New releases are assembled as drafts, verified,
and then published with GitHub immutable-release protection. A new patch is
required for subsequent corrections.

Use `node scripts/verify-release-channel.mjs RECEIPT.json DOWNLOAD_DIRECTORY`
to check the actual downloaded assets against the independently retrieved main
CI receipt, verified client archive and server image identities. The receipt is
a local release-operation input, not a substitute for fetching trusted GitHub
and registry metadata. See [release maintenance](../repository-maintenance.md).

## Remaining boundaries

Team sync remains partial and is not E2E encrypted. Local content encryption does
not encrypt the entire browser profile. Server AgentCaddy handoff and the legacy
server integration runner remain unavailable. The server is single-process per
database. Customer demand, independent human review and off-device recovery
require their own evidence; automated release checks do not establish them.
