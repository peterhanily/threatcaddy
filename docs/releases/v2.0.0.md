# ThreatCaddy 2.0.0

This coordinated client/server release includes the security, data-preservation,
integration and interface work accumulated since 1.0.0. The major version marks
compatibility changes in team sync and account onboarding. The client and team
server are 2.0.0; the independently versioned extension remains 1.1.3.

## Upgrade requirements

- Export and verify an encrypted client archive before changing a bound workspace.
  Save drafts and pause agents. Local IndexedDB upgrades preserve supported data;
  they are not a substitute for an independently recoverable archive.
- Upgrade team clients and their server together. Pushes require the history
  generation returned by cursor pull. Legacy timestamp polling is a full visible
  resync. A generation reset or incomplete historical local queue requires the
  explicit [sync recovery](../../server/docs/sync-recovery.md) procedure.
- The default `invite` registration setting closes self-registration. Existing
  accounts remain; administrators provision new accounts. Legacy allowlist
  entries do not verify ownership of an email address. Plan to sign in again
  after the upgrade; existing account passwords are preserved.
- Preserve the exact JWT keys, database credentials and stable `BOT_MASTER_KEY`.
  If a legacy installation used an ephemeral bot key, inspect protected recovery
  material and encrypted-record presence before stopping it. Generating a new key
  cannot recover ciphertext encrypted under a lost key. Follow
  [credential recovery](../../server/docs/credential-recovery.md).
- Preserve and verify matching database and managed-file backups before migration.
  Startup applies the append-only journal. An older binary alone is not a rollback;
  use the matching restore and history-rotation procedure in
  [deployment](../deployment.md#rollback-and-restore).
- Server-side AgentCaddy handoff and the legacy server integration runner remain
  unavailable. Saved definitions and history are retained. Client integrations
  and team template sharing remain available.

## Changes included

Oversized sync and integration collections are rejected before expensive element
validation, and validation responses and nested-data traversal are bounded.
Node 24.22.2 and patched dependencies replace the previous runtime baseline.
Native password hashing and image processing are exercised in the container gate.

Backups, workspace changes, extension clip delivery, membership enforcement,
integration validation, accessibility and offline workflows have regression
coverage. Sidebar deletion confirmations cover the full viewport. See the
[changelog](../../CHANGELOG.md#v200--2026-11-03) for the complete release summary.

## Downloads and provenance

The [GitHub release](https://github.com/peterhanily/threatcaddy/releases/tag/v2.0.0)
contains the standalone HTML, Chrome and Firefox extension archives, checksums
and a release manifest identifying the exact tested source, verification run,
artifact IDs and immutable server-image digest. Publish those verified bytes;
do not rebuild or substitute downloads after the release gate.

The hosted site, GitHub release, GHCR image, running team servers and browser
stores are separate targets. Extension ZIP version 1.1.3 does not establish a
matching browser-store version. The 1.0.0 downloads remain historical artifacts
and do not contain this release's fixes.

The root dependency audit still records the moderate/low build-tool advisories
described in the [dependency review](../dependency-security-review.md). They are
not suppressed; high/critical findings continue to block publication.

The supported toolchain is Node 24.22.2, pnpm 10.29.1 and npm 11.19.0. Client
TypeScript 6 and server TypeScript 7 use separate package managers and lockfiles.
